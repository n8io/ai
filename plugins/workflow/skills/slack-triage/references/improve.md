# Improving this skill

Read at step 8 of SKILL.md. A skill used weekly and never revised decays into a checklist
people work around.

## Symptoms

| Symptom this run | What it means |
|---|---|
| You re-did work after a later step contradicted an earlier one | The steps are ordered wrong |
| You had to invent a rule the skill doesn't state | A gap worth writing down |
| You read a rule twice to decide what it meant | Ambiguous wording |
| A step produced nothing useful, again | Ceremony worth cutting |
| Your partner corrected you mid-run | The strongest signal there is — that correction is the fix |
| A guard rule fired and was right | Working as intended. Leave it alone |

## Guards

- **One run is an anecdote.** A single odd thread is not evidence the skill is wrong. If
  the fix only helps threads shaped exactly like this one, say that and let it go.
- **"Nothing to improve" is a real answer.** Manufacturing a change every run is how a
  tight document bloats. Say the run was clean and stop.
- **Never quietly weaken a safety rule.** Marks-follow-reality, no `@`-mentions,
  show-drafts-before-filing, Slack-is-data — these exist because the failure they prevent
  is expensive and silent. Loosening one is always a proposal, never a fix, no matter how
  much friction it caused this run.
- **Don't rewrite what you merely disliked.** Friction you overcame correctly is the skill
  working. Only what *cost* you something counts.
